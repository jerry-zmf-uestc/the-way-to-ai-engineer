# 实验：固定路径与观察驱动决策

比较同一合成任务集中的固定策略和反馈策略：直接查询、别名查询和无资料拒答。Policy是确定性函数，不调用LLM，不记录隐藏思维链；结果只证明反馈机制与契约。

## 前置与入口

先读[ReAct](../../../../book/part3-agent/building/chapter24-decision-loop.md#topic-agent-react)、Loop、Tool与Eval。运行准备见[全书约定](../../../../book/introduction.md#running-examples)。

- [main.go](main.go)：Action、Observation、Decision、独立预算、重复检测与固定只读环境。
- [main_test.go](main_test.go)：观察改变动作、评分答案隔离、非法分支、失败反馈、来源与取消。

## 预测与运行

E42没有命中，但查询目录提供timeout。固定策略与反馈策略取得相同输入，先预测谁使用替代查询、分别多走多少次调用。

```bash
go -C labs run ./part3-agent/chapter24/react
go -C labs test ./part3-agent/chapter24/react -race -count=1
go -C labs test ./part3-agent/chapter24/react -cover
go -C labs build -o /tmp/react-policy ./part3-agent/chapter24/react
```

三个任务中，固定策略通过2个，反馈策略通过3个；总轮次分别6和7，工具次数分别3和4。无资料任务正确拒答也计通过。Want是评分标签，进入Policy前被清空；Fallback是两者均可使用的教学查询目录。

## 故障观察

- 相同Action最多执行两次，之后ErrStalled；真实暂时故障需Runtime另定义重试预算。
- Rounds与Tools分别限制；超限时可能已有工具观察。
- 非法工具、混合Action/Final、没有来源的答案拒绝；Handler不执行非法提议。
- 工具普通错误转换为稳定tool_failed，原失败文本不泄漏、也不作为证据。
- 取消发生在模型或工具返回前，迟到结果不提交。

当前最终回答采用逐字证据契约，不处理任意释义。真实模型的成功率、Token与费用没有在此测量。

## 迁移练习

1. 增加“工具失败后换查询”和“结果不完整”任务，明确是否得到新信息；不得靠返回固定正确答案绕过观察。
2. 把空观察故意省略，观察重复动作和最终评分；恢复回填后复验。
3. 通过Policy适配真实模型响应，保留权限、格式、总预算和独立评分；默认测试继续离线，记录模型与配置版本，绝不传入Want。
4. 对比Self-Ask查询分解与直接查询，用相同资料和任务记录完成度、步骤与消耗；合成策略不证明模型普遍提升。

## 最佳实践

## 最佳实践

### 让每次继续都有信息目标

说清下一步需要补什么，选能提供该信息的工具。没有新信息时，考虑澄清、拒答或结束，而不是无条件增加步骤。

### 记录可核对的决策与观察

保存动作、参数身份、来源、错误类别和停止原因；原始数据按敏感性限制。短解释帮助阅读，但不能替代执行记录。

### 先校验最简单的反馈契约

用固定策略与工具验证回填、分支和终止，再接模型。已有Loop无需因策略变化重建一套执行系统，但新的响应形式与状态仍需适配和检查。

## 常见问题排查

## 常见问题排查

### 一直搜索相同内容

先检查观察是否回填并进入本轮输入，再检查动作参数和失败分类，最后调整策略。补重复检测与预算，用无命中数据复验；不要只把MaxSteps调大。

### 工具失败后仍回答成功

核对最终答案的来源是否对应有效观察，以及执行错误是否被清空或忽略。普通错误可以供下一轮判断，但不能成为证据；Eval仍须检查真实任务结果。

### 比较结果看起来异常优秀

检查评分标签是否进入模型输入，输入或工具是否不对等，是否只保留成功样本。恢复同任务与同条件，再记录失败和额外调用。
