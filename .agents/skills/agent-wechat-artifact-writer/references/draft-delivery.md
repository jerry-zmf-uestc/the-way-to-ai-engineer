# 保存与更新公众号草稿

仅在收到保存或更新具体内容的请求时加载。本参考不授予远端操作权限。项目内容规范、用户明确授权与现有审核条件共同决定是否可执行；授权已经充分时不重复确认。

## 准备

- 将目标 AE-ID、候选运行标识、采用的文案/封面/排版与当前用户授权对应，核对内容摘要未在预览后变化。未明确选定版本时先澄清。
- 对正式采用稿运行本地 delivery-check；若用户仅要求保存尚未正式采用的候选，先说明当前审核缺口，不以旧正式稿的通过结果代替候选审核，不自动改状态。
- 加载本机 baoyu-post-to-wechat/SKILL.md，核对当前脚本是否支持所需的新建或更新能力。脚本没有更新能力时不能偷偷改为新建草稿，也不猜测 CLI 参数。
- 复用现有私密凭据配置，仅传给官方 API；不输出配置、access token、secret 或带凭据的 URL。正文、HTML、提示词和普通检查均不需要公众号密钥。

## 复用发布 Skill 的实际边界

按[社区 Skill 复用契约](dependencies.md#f-baoyu-post-to-wechat草稿保存)的F阶段交接：dbs确认版经图片占位映射后作为HTML输入，不重渲染Markdown。当前安装的宝玉脚本使用draft/add，未验证其具备更新入口；不能拿新建命令处理更新请求。若需项目已有官方更新工具，明确其来源与独立能力；缺失则报告阻塞，不自动新建或切换浏览器。

## 素材与目标

公众号交付 HTML 与本地阅读预览是不同产物：去除本地预览提示与重复标题，保证最终文字完整、样式逐元素内联；处理所有图片占位符，核对图的顺序、尺寸、替代说明和封面。不要直接投递带 data URI 或未解析本地路径的浏览器预览。

更新已有草稿时，从私有回执定位目标，再回读公众号账号、草稿标识、标题和当前内容，核对是否发生用户并发编辑。备份可写字段与素材映射到私有 delivery/；发现远端变化先比较，不覆盖。新建须明确是新草稿；结果未知时先查询现有结果。

## 执行与回读

只调用获授权的草稿及必要素材接口，严禁发布、群发、定时发布接口。保存后回读核对标题、摘要、作者、正文文字、图片数量和顺序、封面及本轮实际变更字段；API正常响应不等于显示效果验收。平台清洗或图片问题要记录，必要时交由用户后台预览。

网络超时、连接断开或结果未知时，先查目标及最新内容，避免盲目重复创建或重复写入。鉴权、权限或IP白名单失败时报告具体原因；不循环重试或自行修改安全设置。

私有回执记录操作类型、目标标识、前后内容摘要、时间、实际回读结果和限制，屏蔽凭据。不把素材标识与平台回执提交 Git。不把草稿登记为 published。结束后给用户结果与需要确认的显示问题，线上发布由用户操作。

默认验证仅使用本地替身或静态产物，不为验证 Skill 调用真实公众号。只有本轮明确授权后才执行实际保存。
